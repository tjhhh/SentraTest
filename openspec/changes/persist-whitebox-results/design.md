## Context

Currently, whitebox test data is transient. We need a structured way to store the code provided by the user, the script generated by AI, and the results of every run.

## Goals / Non-Goals

**Goals:**
- Persist Logic and UI code.
- Store the AI-generated Playwright script.
- Save execution statistics and evidence (screenshots).
- Support historical tracking of test runs.

**Non-Goals:**
- Storing the actual binary images in the DB (we store paths/filenames).
- Real-time DB sync of logs during the stream (we save at the end).

## Decisions

### 1. Schema Enhancement
**Decision**: Add a new `Execution` model and update `TestCase`.

**TestCase Updates**:
- `logicCode`: String (The input logic)
- `uiCode`: String (The input UI)
- `generatedScript`: String (The Playwright spec)

**New Execution Model**:
- `id`: UUID
- `testCaseId`: Foreign Key
- `stats`: JSON (total, passed, failed, duration)
- `results`: JSON (detailed test items)
- `screenshots`: JSON (array of filenames)
- `exitCode`: Int
- `createdAt`: DateTime

### 2. Implementation Flow
**Decision**: Save `TestCase` during the `/generate` call and `Execution` at the end of the `/run` call.

### 3. Dashboard Integration
**Decision**: Create a new `System` controller to handle aggregate dashboard data.

**API Endpoints**:
- `GET /api/system/stats`: Returns counts and percentages for dashboard cards.
- `GET /api/system/recent`: Returns the last 10 executions with related test case data.

**Frontend Update**:
- Modify `Dashboard.tsx` to fetch from these endpoints on mount.
- Replace static `stats` and `recentTests` arrays with state populated by the API.

## Risks / Trade-offs

- **[Risk] Large Code Bloat** → Mitigation: Use Postgres `TEXT` or `JSONB` fields which handle large strings efficiently.
- **[Risk] Schema Migration in Production** → Mitigation: Use `prisma migrate deploy` in the Docker entrypoint (already implemented in docker-compose).
- **[Risk] Dashboard Latency** → Mitigation: Use Prisma's `_count` and selective field selection to ensure the stats query is fast even with thousands of records.
